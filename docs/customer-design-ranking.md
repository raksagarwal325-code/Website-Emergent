# Customer design ranking

The first-stage DINOv2 model, original vectors, exact identity checks and similarity thresholds are retained. When the leading non-exact result is ambiguous (score 0.80–0.90 and lead under 0.05), compare at most 60 existing strong candidates using 32 spatially distributed DINOv2 patch descriptors. A candidate is promoted only with a detail score of at least 0.55 and a lead of 0.01; all other candidates keep their original relative order. The label is “Closest design”, never an exact SKU claim.

Existing exact matches, high-confidence results and uncertain fallback-only results bypass this step. Missing, invalid or incomplete detail features retain the original ordering. The same pinned model extracts details; no additional model or external AI API is used. Each stored descriptor is at most 24 KiB using checked float16 bytes.

The background indexer backfills design_vectors and design_version within existing index rows. It retains existing global vectors and the current INDEX_VERSION. Query requests never download catalogue photos or model weights. Admin image-index status includes design_indexed; original search remains available while details prepare.

customer_design_relations.json contains owner-reviewed product relationships as catalogue data. The initial four-SKU similar-design group is CH-029/044/051/053, confirmed by the owner on 2026-09-29. These are alternatives, not assertions of identical configuration. Only products in the currently published catalogue with unambiguous SKUs and the same category can be included. Related items follow all exact matches or the leading design, with no duplicates. New relationships require review; uploaded photos do not automatically create them.

This is separate from quotation and does not alter product galleries, source photographs, the three existing search references or product records. Existing JPG/PNG/WebP and upload size limits remain.

Full-catalogue runtime evaluation: https://github.com/raksagarwal325-code/Website-Emergent/actions/runs/36511742447 . Complete coverage was 544 products / 1,092 images. Across 104 queries, expected-product ranks had zero regressions and 101 queries retained the exact same SKU order. CH-029 moved from rank 6 to rank 1 for the original and from outside the 12 returned results to rank 1 for a compressed copy. CH-044, CH-051 and CH-053 followed via the explicitly owner-reviewed relationship group. The third changed query was a CH-029 catalogue control gaining these alternatives. All other controls, earlier reference photos, independent customer photos and background exclusions kept their SKU order. Additional offline comparison time peaked at 0.151 seconds; this excludes database and network latency.

No new environment flag is required. After syncing/restarting, the detail index fills in the background. Until the required shortlisted images have valid detail features, searches retain their existing ordering. Keep the existing CUSTOMER_IMAGE_REFERENCE_MANIFEST setting for the prior three approved reference photos. Reverting this code restores the previous ranking; the old global index remains usable and extra detail fields can be ignored. Seeded reference recognition is not evidence of new-photo generalisation. The owner's full approximately 30-photo successful set is not available. No merge or production deployment is included.
